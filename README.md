# ML Rollout Error Amplification

**Code and saved experiment outputs for _From One-Step Errors to Long-Horizon Rollouts: Realized Error Amplification in Learned Dynamics_.**

This repository studies a machine-learning question that arises in learned simulators and autoregressive dynamical models:

> **How do small one-step model errors become long-horizon rollout errors?**

The experiments treat rollout error as a forced finite-time propagation problem. Local model defects are repeatedly injected into a learned dynamical system, propagated by trajectory-dependent Jacobian products, projected across the singular spectrum, and finally combined constructively or destructively at the forecast horizon.

The current study uses **Lorenz–96** with a **residual MLP surrogate** and analyzes worst-case transient growth, realized defect amplification, vector cancellation, spectral participation, and finite-amplitude perturbations.

**Paper:** arXiv link will be added after the v1 upload.

## Environment

The reported experiment environment was:

- **Python 3.13.14**
- **PyTorch 2.14.0+cpu**
- **CPU PyTorch build**

NumPy and Matplotlib are also required. Their exact versions were not supplied, so this repository does not invent version numbers.

```bash

cd ml-rollout-error-amplification

python -m venv .venv
```

Linux/macOS:

```bash
source .venv/bin/activate
pip install -r requirements.txt
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## Run the five-seed machine-learning campaign

Windows:

```powershell
.\run_primary_campaign.ps1
```

Linux/macOS:

```bash
chmod +x run_primary_campaign.sh
./run_primary_campaign.sh
```

The campaign trains independently seeded residual MLP surrogates and evaluates forecast horizons
`1, 2, 5, 10, 20, 40, 80, 160`, including Jacobian/SVD diagnostics, propagated model defects,
PGD perturbations, and epsilon sweeps.

## Regenerate the paper figures from the saved results

The MATLAB script pools the saved seed-level campaign tables. It expects `results/seed_*/` and
writes the resulting PDFs to `figures/`. The plotting workflow uses the diagnostic, perturbation,
epsilon, spectral-mode, and defect-term tables. This is the same directory convention documented
inside the MATLAB source.

Because each raw `spectral_modes_campaign.csv` is about 60 MB, those five files are stored as
compressed `.csv.gz` files in Git. Restore them first:

```bash
python prepare_results.py
```

Then, from MATLAB with the repository as the working directory:

```matlab
generate_all_figures
```

MATLAB's **Statistics and Machine Learning Toolbox** is required by the supplied plotting script.

## Main saved data products

Each `results/seed_<seed>/` directory contains:

- `diagnostic_campaign.csv`
- `defect_terms_campaign.csv`
- `spectral_modes_campaign.csv.gz`
- `perturbation_campaign.csv`
- `epsilon_campaign.csv`
- `epsilon_sweep.csv`

The generated PDFs and PyTorch checkpoints from the original result folders are deliberately not
tracked here: the CSVs are the data required by the supplied MATLAB figure-generation workflow,
while checkpoints can be regenerated by rerunning the campaign.

## Scientific quantities

For the learned one-step map \(x_{k+1}=f_\theta(x_k)\), the finite-time propagator is

\[
\Phi(t,T)=J_{t+T-1}\cdots J_t,
\qquad
J_t=\frac{\partial f_\theta}{\partial x}(x_t),
\]

with worst-case finite-time amplification

\[
G_{\max}(t,T)=\sigma_1^2(\Phi(t,T)).
\]

For one-step model defects

\[
e_k=f_\theta(x_k)-x_{k+1},
\]

the first-order rollout-error model is

\[
\delta x_T^{\mathrm{lin}}
=
\sum_{k=0}^{T-1}\Phi(T,k+1)e_k.
\]

The central distinction in the analysis is between **how strongly the learned dynamics could
amplify a perturbation** and **how strongly the actual model defects are amplified and combined**.
